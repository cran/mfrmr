mfrmr Workflow

Choose the result you need

Start with the intended score and decision, then choose a branch. These are connected workflows, not a checklist requiring every analysis.

Before any branch, record the meaning of low and high scores. A column named Comprehensibility may encode ease or difficulty. Higher Person locations predict higher coded categories; they do not inherently mean better performance. With the default Rater orientation, higher locations predict lower coded scores. See score direction before interpreting severity, bias, plots or anchors. Changing positive_facets is not reverse-coding the outcome.

If Content and Organization are separate reported scores, start with the criterion-versus-score distinction. A Criterion facet in one-dimensional MFRM does not estimate a separate ability for each criterion. Multivariate G theory estimates cross-score covariance components; it does not fit multidimensional IRT.

An assignment graph is especially useful for explaining why adding a shared performance or rater might improve linking. The current feature API does not supply those steps automatically.

Quick start

By the end of this lesson you should be able to prepare one-rating-per-row data, estimate abilities and facet effects, identify results needing review, and save an analysis with its assumptions. Start with the synthetic example, then adapt the CSV lesson. Follow-up analyses are optional and should answer your assessment question.

This tutorial follows the ordinary fixed-facet fit_mfrm() workflow. To plan the number of tasks or raters for an observed score, use Plan an assessment with G theory; no MFRM fit is required for that workflow. To choose between fixed facets, shared random raters and Person-specific testlets, use mfrmr_output_guide("models") or help("mfrmr_workflow_methods"). The extended models have dedicated tutorials: vignette("mfrmr-random-raters", package = "mfrmr") and vignette("mfrmr-testlets", package = "mfrmr"). Their prediction targets and reporting support differ. The diagnostics and reports below follow ordinary RSM/PCM fits. Two-family GPCM and corrected JML also have class mfrm_fit, but require their model-specific result routes; sharing that class does not make these ordinary diagnostics available. See gpcm_capability_matrix() and vignette("mfrmr-gpcm-scope", package = "mfrmr") before changing model family.

This example estimates person abilities while accounting for rater severity and criterion difficulty. A facet is a source of variation in scores; here, Rater and Criterion are facets, and individual raters and criteria are their levels. The data are synthetic, with one row per rating and scores from 1 to 4.

The example data are included in the package. The loading line below creates ratings; you do not need to prepare a file or construct the scores first. head(ratings) shows the first six rows. The quoted column names in fit_mfrm() are case-sensitive; Study and Group are extra labels unused by this model. MML selects marginal maximum likelihood; RSM selects a rating-scale model with shared category thresholds (the transitions between adjacent scores). The rubric uses scores 1 through 4. category_policy = "preserve" keeps that category ladder; it prevents an unobserved intermediate category from being silently collapsed into a different scale.

# Load the package
library(mfrmr)

# Load example ratings and look at the first six rows
ratings <- load_mfrmr_data("example_operational")
head(ratings)

# Fit the model
fit <- fit_mfrm(
  data = ratings,
  person = "Person",
  facets = c("Rater", "Criterion"),
  score = "Score",
  rating_min = 1, rating_max = 4,
  category_policy = "preserve",
  method = "MML",
  model = "RSM"
)

# Plot the results (Wright map)
plot(fit)

# Save the summary, then display its tables
results <- summary(fit)
results$person_overview # One row summarizing person ability estimates
results$facet_overview  # One row per facet: number of levels, mean, SD, range

# Check the interpretation status and recommended next step
results$decision

<- saves an object without printing it. Here ratings holds the data, fit holds the model, and results holds its summary. $ selects a named part: results$person_overview displays just that table. Enter results to print the full summary.

The Wright map displays the estimates in logits, the model’s measurement units, rather than the original 1-to-4 scores. With this example’s default orientation, higher person estimates mean higher ability; higher rater estimates mean stricter ratings, and higher criterion estimates mean greater difficulty.

The native models use the logistic metric (L-metric), with D = 1: there is no extra 1.7 or 1.702 normal-ogive approximation factor. In this RSM example, an ability increase of one unit raises each adjacent-category log odds by one, holding other parameters fixed. For GPCM, the effective discrimination multiplies that change. A normal ability distribution is a separate assumption and does not change the response link. See ?fit_mfrm for scale conventions.

The overview tables describe distributions: person_overview has one row for all 48 persons, and facet_overview has one row for each facet. Mean/MeanEstimate is the average, SD/SDEstimate is the spread, and Min/Max or MinEstimate/MaxEstimate give the endpoints. Rater and criterion means are constrained to zero here; their SDs and ranges show differences among levels.

Inspect individual estimates

estimates <- as.data.frame(fit)
head(subset(estimates, Facet == "Person")) # First six persons
subset(estimates, Facet == "Rater")       # All raters
subset(estimates, Facet == "Criterion")   # All criteria

Facet identifies the type of estimate, Level identifies the person, rater, or criterion, and Estimate is its value in logits.

Check what needs review

Read results$decision, especially Why and NextAction, before interpreting or reporting estimates. FormalInference = "No" in this first summary can mean that precision has not yet been reviewed; it does not necessarily mean that fitting failed. The default summary does not compute diagnostics.

diagnostics <- diagnose_mfrm(fit)
diagnostic_summary <- summary(diagnostics)
diagnostic_summary$decision

For your own data, follow Use your own CSV below. For reporting, res <- mfrm_results(fit, diagnostics = diagnostics) builds a comprehensive object that reuses the checks above. Pass res to mfrm_report() or export_mfrm_results(); results remains the basic summary.

Use your own CSV

The goal here is to estimate person ability while accounting for rater severity and criterion difficulty in your own ratings. Start with the same row layout as the packaged example: one score from one rater for one person on one criterion. For example:

Person Rater Criterion Score
001 R1 Content 3
001 R1 Style 2
001 R2 Content 4
001 R2 Style 3

The repeated 001 is intentional: all four scores belong to the same person. Keep IDs consistent across rows. These four rows explain the layout; use the complete set of ratings for estimation. Score contains the ordered integer categories from the rubric, not totals or averages across raters. This example uses two non-person facets; choose facets that represent your design.

1. Read and inspect the file

You can practice the full workflow without supplying a file. This block writes the packaged synthetic ratings to a new temporary CSV:

library(mfrmr)
csv_path <- tempfile(fileext = ".csv")
write.csv(load_mfrmr_data("example_operational"), csv_path,
          row.names = FALSE, na = "")

For your own data, export your rating sheet as CSV UTF-8, with column names in the first row. Skip the practice block above and select your file instead:

library(mfrmr)
csv_path <- file.choose()

For a reusable script, replace file.choose() with a quoted path such as "data/ratings.csv", relative to the folder shown by getwd(). Both routes now use the same import and analysis code:

ratings <- read.csv(
  csv_path,
  colClasses = "character",
  na.strings = "",
  check.names = FALSE,
  fileEncoding = "UTF-8-BOM"
)
# Treat the documented missing-score marker only in the score column
ratings <- recode_missing_codes(ratings, columns = "Score", codes = "NA")
head(ratings)
names(ratings)
table(ratings$Score, useNA = "ifany")

Reading columns as text preserves distinct IDs such as 001, 1, and NA; mfrmr converts numeric score strings such as "3" for estimation. check.names = FALSE preserves the headers. Empty cells are missing in every column; the literal marker NA is recoded only in Score. Use the missing-score markers declared for your data. Zero is a score when the rubric includes zero, and must not be used to fill unassigned rating cells.

The quoted column names in the next two steps must match names(ratings), including capitalization and spaces. You do not have to rename your file’s columns. For headers Student, Judge, Task, and Rating, change the arguments in both describe_mfrm_data() and fit_mfrm() as follows:

Argument Four-column example Your alternative headers
person "Person" "Student"
facets c("Rater", "Criterion") c("Judge", "Task")
score "Score" "Rating"

Also use columns = "Rating" in the recoding call and inspect ratings$Rating instead of ratings$Score. Extra columns such as the practice file’s Study and Group are unused by this model.

2. Review the rows and the rubric

Set the minimum and maximum from the rubric, not the observed minimum and maximum in this sample. The code below describes a 1-to-4 rubric. Keep the same values in the data review and the fit. category_policy = "preserve" preserves the intended category structure, including categories with no observations.

data_review <- describe_mfrm_data(
  data = ratings,
  person = "Person",
  facets = c("Rater", "Criterion"),
  score = "Score",
  rating_min = 1,
  rating_max = 4,
  category_policy = "preserve"
)
data_review$row_retention
data_review$missing_by_column
data_review$score_distribution
data_review$design_connectivity

Read these four tables in order:

  • row_retention: compare input and retained Rows; inspect any DroppedRows. A missing score or required ID removes that rating row, not automatically the person’s other ratings. The package does not fill missing ratings.
  • missing_by_column: locate missing input values. Non-numeric score text can also cause row loss; inspect warnings and data_review$preparation_notes when the retained count is unexpected.
  • score_distribution: RawN counts the retained ratings in each category. A zero count in an internal category, such as 3 on a 1-to-4 scale, prevents fitting with category_policy = "preserve". Review the data and rubric before changing categories; increasing optimizer iterations cannot supply missing category information.
  • design_connectivity: Components = 1 means a facet’s levels are connected through shared persons. More than one component needs design review before comparing levels across components. Connectivity alone does not establish full model identification.

For the practice CSV, all 282 input rows are retained, all four categories have observations, and each facet has one connected component. Six planned ratings are absent from the file; column missing counts cannot detect absent rows. If you have a planned assignment roster, pass it as expected_design to describe_mfrm_data() to assess these omissions. The applied example later in this vignette shows how. Without a roster, structural missingness is reported as not assessed; a complete person-by-rater-by-criterion crossing is not assumed.

3. Fit and read the results

After resolving the data-review findings, fit the same rows, columns, and rubric. This example uses an RSM with shared category thresholds; the choice should reflect the scoring design. Diagnostics then supply evidence for the interpretation decision.

csv_fit <- fit_mfrm(
  data = ratings,
  person = "Person",
  facets = c("Rater", "Criterion"),
  score = "Score",
  rating_min = 1,
  rating_max = 4,
  category_policy = "preserve",
  method = "MML",
  model = "RSM"
)
csv_diagnostics <- diagnose_mfrm(csv_fit)
csv_results <- summary(csv_fit, diagnostics = csv_diagnostics)
csv_results$decision

Read Why and NextAction before using the estimates. A FormalInference value of "No" means that the stated obstacle to formal use still needs attention. Diagnostic plots can help investigate it. Even a supported precision decision does not establish the validity of the assessment or answer the study’s substantive question.

plot(csv_fit)
csv_estimates <- as.data.frame(csv_fit)
head(subset(csv_estimates, Facet == "Person"))
subset(csv_estimates, Facet == "Rater")
subset(csv_estimates, Facet == "Criterion")

Level identifies the person, rater, or criterion; Estimate is the fitted value in logits. With these defaults, higher person values mean higher ability, higher rater values mean stricter ratings, and higher criterion values mean greater difficulty. The rater and criterion estimates are centered at zero within each facet. In the practice file, R06 is about +0.41 and R01 about -0.61: R06 is estimated to rate more strictly after accounting for person ability and criterion difficulty. This difference alone does not establish statistical significance.

With custom facet names, change the Facet filters too, for example from "Rater" to "Judge"; person rows retain Facet == "Person" even when the input ID column is named Student. To inspect all persons, remove head(). The overview tables in csv_results summarize distributions; the rows in csv_estimates give individual estimates.

The example has 282 observed ratings from 48 persons, six raters, and three criteria. All observed rows are retained. The package does not assume that every rater scored every person.

Record the estimator, model, score coding, constraints, and numerical settings. For this RSM, MML uses a standard-normal person distribution; reported person scores are EAP estimates, and non-person facets are fixed effects centered within facet. RSM shares category thresholds. Choose PCM with an explicit step_facet when the rubric and question call for separate thresholds.

The default MML grid is 31 quadrature points. A comparison that could change the study’s conclusion needs a prespecified denser common-grid sensitivity check with mml_quadrature_sensitivity(). A temporary 7-point grid is only a computational screening run. maxit is a computational ceiling, not a convergence criterion; inspect ConvergenceStatus and Numerical before increasing it. Keep the same data, model, method, and planned controls when investigating an iteration limit. Choose JML for its fixed-person estimand when appropriate, not as a faster substitute for MML.

summary(fit)$numerical_review distinguishes optimization, curvature, starting values and integration, with a next action for each. To preserve inputs and constraints, use build_mfrm_replay_script(fit) with the original input data before changing a diagnostic control. Ordinary mml_starts and automatic integration cannot be combined: review specified starts on a shared fixed grid, then run mml_quadrature_sensitivity() separately. 3. Identify what needs closer inspection

Are the rating categories working as intended? Examine category use and the transitions between scores on the declared rubric:

scale_toy <- rating_scale_table(fit_toy, diagnostics = diag_toy)
scale_toy$category_table[, c("Category", "Count", "AvgMeasure", "ExpectedMeasure", "Infit", "Outfit")]
scale_toy$model_context
scale_toy$owner_category_table[, c(
  "StepFacet", "CategoryLabel", "RawCount", "Count", "Percent", "UsageStatus"
)]
scale_toy$threshold_table[, c("StepFacet", "Step", "Estimate", "SE", "CIUse")]
plot(scale_toy)
scale_toy$notes

AvgMeasure is the average oriented generating measure among responses in each observed category; ExpectedMeasure is its model expectation. Category residual mean squares are descriptive and have no universal unit baseline.

StepOwner tells you which facet supplies the thresholds. This RSM has one Common family, so its owner counts describe the whole sample. With PCM, step_facet = "Criterion" gives counts and thresholds for each criterion; step_facet = "Rater" gives them for each rater. Choose the owner from the rubric and analysis question. Criterion-owned thresholds cannot describe differences in raters’ threshold spread.

RawCount counts rating rows; Count sums their weights, and Percent uses the total weight within the indicated owner level. These are not counts of independent persons. A category unused by one owner can be common overall. UsageStatus distinguishes unobserved categories, zero-weight observations and owners with no ratings; the last have unavailable percentages. An observed zero does not establish that a category is structurally impossible.

The threshold table reuses SEs and intervals from the supplied diagnostics. Check SE_Status, CIUse and UncertaintySourceStatus before reporting them. Without diagnostics, the same call returns counts and fitted threshold points without requesting covariance calculations; its SEs are unavailable. Notes remain in the returned object, outside the plot.

The bars show observed category counts; the line shows fitted expected counts. Look for rarely used categories, changes in average person measure across categories, and threshold order. Explain the observed pattern in terms of the rubric. A warning is a reason to investigate, not an automatic instruction to merge categories.

Which ratings differ most from model expectations? This example uses an explicit exploratory rule and shows up to ten cases:

unexpected_toy <- unexpected_response_table(

Further analyses should answer a stated question

For observed rating agreement, start with the rating-agreement tutorial. Its small runnable example shows how to match person-by-task records, distinguish correlation from agreement, compare a score source with a reference, and audit missing pairs without fitting another model. It also explains why these coefficients answer a different question from rater severity or separation reliability.

For prior sensitivity or an external Bayesian extension, use export_mfrm_model() with a unit-weight RSM/PCM or one-family GPCM MML fit on the fixed N(0,1) ability scale. Both Stan and brms retain supported fixed facet anchors and group means. This example reuses the RSM fit above:

Each directory contains code, data, category/level mappings and run.R. stan_model$output_dir and brms_model$output_dir locate these practice bundles; replace tempfile() with a study directory to retain them. The category table maps the external model’s integers back to the original rubric. model_data$levels identifies the Persons and facet levels, and model_data$step_owners identifies the shared RSM or facet-specific PCM steps. Set location_prior_sd and step_prior_sd in export_mfrm_model() when creating a bundle for a different prior choice; both formats use those values. Review its README and priors, then run the script from that directory with CmdStanR/CmdStan installed (and brms for the second format). Export itself needs neither backend. Both formats preserve adjacent-category probabilities, the fixed standard-normal ability scale, facet signs and constraints, and unordered step offsets with their original sum constraints. Their explicit structural priors make this a Bayesian analysis; it does not reproduce MML point estimates or qualify frequentist interval coverage. Two-family GMFRM also supports Stan export, with explicit component log-slope priors and a slope-levels.csv mapping; see the two-family workflow. One-family GPCM uses log_slope_prior_sd in both formats, with geometric-mean-one slopes. For brms, the source must use gpcm_mml_identification = "fixed_standard_normal". The default one-family GPCM estimates the population mean and variance. You can export its intercept-only population to Stan with population_prior = list(mean = c(0, 1), log_sd = c(0, 0.5)); each pair gives the location and scale of a normal prior. The mean and SD are sampled while relative slopes and anchors retain the native metric. brms still requires the fixed-population specification. Changing that setting changes the model; do not change it merely to enable export. Review prior predictions and sensitivity.

Anchor values are exact constraints. levels.csv and steps.csv in anchored or one-family bundles show the prior means, marginal SDs and fixed coordinates. A zero SD reflects a fixed value, not evidence that its earlier calibration was certain. The scope excludes JML/Person anchors, two-family brms, nonunit weights, population regression, interactions and shrinkage. Native two-family fitting still excludes anchors. Inspect sampler diagnostics and prior sensitivity before using the posterior. Exported ratings and original labels require the same sharing review as an analysis archive. See ?export_mfrm_model for supported post-processing and prediction targets.

After sampling, start with summary-decision.csv: it states the sampling review and next action before presenting estimates. sampling-review.csv lists the checks and criteria. parameter-summary.csv keeps original labels, the meaning of larger values, fixed/estimated status and interval status beside the numbers. Fixed values have no estimated interval; finite intervals for estimated values can still require sampling review. Both formats support Rscript run.R --summarize to rebuild these reports from saved draws without sampling again. A clean sampling screen does not establish model validity.

Question Follow-up
How uncertain is a specified difference between two raters? mfrm_facet_intervals() uses their covariance; choose the model-based or sandwich method for the sampling assumptions. Attach the result with mfrm_results(fit, intervals = ...). See mfrmr-facet-intervals; an ordinary Wright map does not switch to sandwich intervals.
Do category thresholds need to differ by criterion? compare_mfrm() and mml_quadrature_sensitivity(); fit candidates to the same observations and review numerical sensitivity.
Which facet combinations merit closer review? estimate_all_bias(fit) explores all non-Person pairs. summary(screens)$overview shows availability and magnitude; $cells preserves signed shifts and counts. Use plot(screens) and plot(screens, pair = "Rater x Criterion") for overview and detail. These conditional screens have no collection-wide multiplicity control.
Do prespecified rater-by-criterion or group contrasts depart from the model? estimate_bias() supplies conditional screening evidence; analyze_dff() has its own scope. For jointly fitted interactions, see fit_mfrm(facet_interactions = ...) and interaction_effect_table(). Specify the target, supported inference route and multiplicity plan before inspecting results. See the reporting vignette and mfrmr-linking-and-dff.
How often does a declared rater-warning rule detect a specified departure or falsely flag an unaffected rater? mfrm_screening_performance() with known simulation truth and all planned trials. See mfrmr-screening-performance for individual/family rates, unavailable results and Monte Carlo uncertainty.
Would the conclusions change under a GPCM? gpcm_capability_matrix() and mfrmr-gpcm-scope; explain what discrimination reweighting means for the score interpretation.
Are scores missing from assigned rating events? Start with the assignment roster, then review_mfrm_imputations(), fit_mfrm_imputed() and pool_mfrm_imputed(). See mfrmr-response-imputation for an explicit imputation model; the review function does not generate scores. Do not fill unassigned combinations.
Do external attributes describe different groups of persons, raters or tasks? mfrm_features() with PCA/k-means for numeric features, or PAM/hierarchical clustering for mixed features. See mfrmr-external-features for missing attributes, group stability and links back to rating events. Groups are not ability classes or judgments of rater quality.
Would more raters or tasks improve observed-score dependability? mfrm_g_study() followed by mfrm_d_study(); declare the observed-score design, candidate plans and any composite weights. Their help explains G/Phi and SEM. These coefficients describe observed scores, not MFRM latent abilities.
Are forms or waves on a comparable scale? mfrmr-linking-and-dff and mfrmr-portable-calibration; common labels alone do not establish linking.
How does a proposed rating design perform under stated assumptions? build_mfrm_sim_spec(), simulate_mfrm_recovery(), and assess_mfrm_recovery(); report generating conditions, repetitions, failures, and Monte Carlo uncertainty.
How should new persons be scored under an existing calibration? predict_mfrm_units() and sample_mfrm_plausible_values(); reuse an eligible fitted calibration and report the conditioning assumptions.
How certain is a person’s placement relative to supplied ability cuts? For ordinary RSM/PCM, use cut_scores in the eligible scoring API and inspect $decisions. apa_table(..., which = "decisions") retains probabilities, priors and review states. Check whether the scoring prior represents the target population; numerical checks do not establish that match. See mfrmr-portable-calibration for interpretation and saved-score reporting; calibration and estimated-prior uncertainty are excluded.

For repeated simulation work, supply file to simulate_mfrm_recovery() or evaluate_mfrm_design(). An identical call reads a finished result or resumes saved trials after interruption. For example, create a results directory once and keep this call in the analysis script:

dir.create("results", showWarnings = FALSE)
recovery <- simulate_mfrm_recovery(
  n_person = 50, n_rater = 4, n_criterion = 4,
  reps = 100, seed = 20261021, file = "results/recovery.rds"
)
summary(recovery)$rep_overview  # Retains failed attempts, too.

The default file_refit = "never" rejects a file whose inputs, fitting controls, replication count, RNG kind or implementation/software identity differ. Use a new path to preserve both studies, or explicitly choose "on_change" to replace an incompatible study. "always" starts again even if the file matches. After completion, ordinary readRDS() also loads the result and its reproducibility metadata. Save the script and software environment with it; seed recording is not a guarantee of identical numerical results on every platform. See ?simulate_mfrm_recovery for checkpoint boundaries and parallel resumption.

For an injected Group-by-Criterion or Rater-by-Criterion departure, evaluate_mfrm_signal_detection() summarizes the behavior of the selected screen. Start with summary(x)$detection_summary: compare the planned and available counts before interpreting a rate. Non-target rates average the available-cell proportion within each contributing trial; they are neither pooled-cell rates nor the probability of any false flag. Inspect x$rep_overview for failed stages and seeds, and x$results for target-level unavailability reasons. This helper uses saveRDS() for saving the returned result, without the checkpoint arguments shown above.

DIF contrasts are reference minus focal. A residual-score difference is not the injected latent effect; a subgroup location difference requires common-scale linking before its mean is reported. The bias shift is relative to the fitted baseline. These summaries do not establish effect recovery or calibrated power. Residual DIF tests remain unavailable, and refit/bias rates remain screening summaries. See ?evaluate_mfrm_signal_detection for denominators, Monte Carlo uncertainty and interpretation of older saved results.

When starting from extract_mfrm_sim_spec(fit), inspect the proposed generating mechanism. Without a population regression, the Person spread is the SD of the reported estimates; shrinkage and measurement error mean it need not equal the latent population SD. With a population regression, the stored coefficients, residual variance, transformations and factor coding define Person generation. The generating parameters remain fixed across replications. Monte Carlo SEs measure the precision of the simulation averages under those assumptions; they do not measure uncertainty in the original fit or validate future forecasts. When covariates and observed assignments belong to the same template Persons, use population_assignment = "matched" (the default for newly built/extracted specifications). Matching TemplatePerson IDs preserve the association between covariates, groups and assignment patterns. Choose "independent" only when breaking that association is part of the intended scenario. A population Group column also defines the response group; conflicting group definitions are rejected. Truth metadata retain the selected source template IDs.

Observed skeletons preserve repeated rows and weights. Each row generates a new conditionally independent rating; dependence across occasions or among peer reviewers requires a different generating model. Remove accidental source duplicates before building the specification. Weights affect fitting and do not create extra generated responses. Older saved specifications without population_assignment keep independent template draws; rebuild them and use a new study file for matched sampling.

For a manual refit of generated latent-regression data, take both person_data and population_formula from attr(simulated_data, "mfrm_population_data"). The formula-compatible terms object retains the template’s transformation basis and factor coding. Rewriting it as a fresh ~ scale(X) formula would relearn the scaling on the new cohort. Old transformed specifications without the stored basis must be rebuilt from the original template or fit and saved as a new study.

Read recovery results as relative parameter recovery under the declared generating conditions. summary(recovery)$recovery_summary reports RMSE and its Monte Carlo SE across independent trials. Mean-aligned group bias is zero by construction, so a small value does not establish unbiased estimation of each parameter. PCM/GPCM comparisons account for the facet shift induced by centering the generating step thresholds.

For interval evidence, read Coverage95 together with ExpectedRows, CoverageRows, CoverageAvailabilityRate, McseCoverage95 and FailedReps. Coverage is conditional on obtaining a valid interval; failures and unavailable intervals remain visible separately. Non-Person MML facet coverage uses each level’s deviation from its facet mean with the matching covariance. JML point recovery and Person scores remain useful, but their source uncertainty is not treated as that structural interval; inspect CIReason in recovery$recovery or CIReasons in the summary. Unknown target rosters produce NA rates, not zero or successful outcomes. assess_mfrm_recovery(recovery)$uncertainty_review keeps these counts and reasons with its checklist.

For older saved objects, summary(), assessment and summary/coverage plotting recalculate the aggregates without fitting. They withhold legacy coverage when the required covariance was not saved. A new run is needed for corrected PCM/population truth mapping and matching interval evidence; retain the old file as a separate study. The help page explains which fields can be recovered.

For stability against an observed-data reference, use build_mfrm_resampling_spec() and draw_mfrm_resamples(). They resample entire Person clusters within optional strata, retaining all ratings for each selected Person. A same-size bootstrap requires design = "stratified_bootstrap", sample_fraction = 1, and topup_preserve_facets = FALSE; the default fraction is one half. Adding Persons to restore missing facet levels changes the sampling distribution. Read sampling_scheme and the base/added/final counts in the manifests. Person resampling holds the observed non-Person facets fixed; it does not reproduce sampling new raters/tasks or dependence among Persons in a peer-review network. Full-data estimates are uncertain references, not known truth, and these helpers do not qualify bootstrap confidence intervals.

Missing attributes and missing rating scores need different models and workflows. Neither clustering nor response-score imputation is a prerequisite for ordinary MFRM analysis. G/D-studies start from observed scores and their design; do not substitute MFRM estimates or testlet variances for their input. For these branches, mfrmr_output_guide("features"), mfrmr_output_guide("imputation") and mfrmr_output_guide("gtheory") identify the supported summaries and plots. Save their full objects with saveRDS(); they have dedicated output routes and are not mfrm_results() inputs.

Simulation examples with one or two repetitions test the computational setup; they do not estimate operating characteristics adequately for a paper. A simulation’s assumptions and results also do not replace evidence from the observed assessment. Keep these analyses in the report only when their role in answering the study question is clear.

An observed writing-assessment example

The optional sirt package supplies data.ratings1, observed German-writing ratings from a 2009 Austrian educational standards survey. Its 274 rows contain 135 students, seven observed raters and five rubric criteria scored 0 to 3. The data documentation describes the source. This dataset is separate from mfrmr’s synthetic examples.

The practical question is which differences in severity, category use or consistency merit discussion with a rater. The example below uses a PCM so criteria can have different category thresholds. It assumes a common writing scale and conditionally independent ratings; inspecting the output does not establish those assumptions. Repeated rubric ratings of one performance may still share influences that this model does not represent.

Run this optional example after installing sirt. It is not run when building this vignette. Display aliases replace source identifiers in the example’s tables; aliases do not make a rating archive anonymous.

library(mfrmr)
data("data.ratings1", package = "sirt")
wide <- data.ratings1
persons <- match(wide$idstud, unique(wide$idstud))
raters <- match(wide$rater, unique(wide$rater))
writing <- do.call(rbind, lapply(paste0("k", 1:5), function(criterion) {
  data.frame(
    Person = sprintf("P%03d", persons), Rater = paste0("R", raters),
    Criterion = criterion, Score = wide[[criterion]]
  )
}))
review <- describe_mfrm_data(
  writing, person = "Person", facets = c("Rater", "Criterion"), score = "Score",
  rating_min = 0, rating_max = 3
)
review$row_retention
review$design_connectivity

writing_fit <- fit_mfrm(
  writing, "Person", c("Rater", "Criterion"), "Score",
  method = "MML", model = "PCM", step_facet = "Criterion",
  rating_min = 0, rating_max = 3, quad_points = 61, maxit = 400
)
writing_diagnostics <- diagnose_mfrm(writing_fit, residual_pca = "none")
feedback <- facet_quality_dashboard(
  writing_fit, diagnostics = writing_diagnostics, facet = "Rater"
)
feedback$detail[, c("Level", "N", "Estimate", "SE", "Infit", "Outfit", "MisfitFlag")]
feedback$settings
plot(writing_fit, type = "rater_severity", diagnostics = writing_diagnostics, facet = "Rater", show_bands = FALSE)
saveRDS(feedback, "writing-feedback.rds")
archive <- export_mfrm_bundle(
  writing_fit, diagnostics = writing_diagnostics, facet = "Rater",
  output_dir = "writing-analysis", data = writing, acknowledge_sensitive = TRUE
)

Reshaping gives 1,370 criterion ratings; the 274 original rows are not the number of students. Each rater has 185 to 205 criterion ratings here. The example produces a low-Infit flag for R7: unusually predictable ratings also trigger this screen. This is a prompt to inspect rubric use and individual ratings, not evidence that R7 is inaccurate or should be removed. Severity and consistency answer different questions, and this dataset supplies no known true rater quality against which to validate either interpretation.

The quadrature setting belongs to this example; use mml_quadrature_sensitivity() when numerical sensitivity matters to a comparison. Preserve the dashboard’s notes, review rating-category use and common-person coverage, and use the actual scripts or rubric descriptors in feedback discussions. A different-looking result alone does not establish that a rater needs training or that training would improve the scores.
