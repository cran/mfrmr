mfrmr Linking and DFF

This vignette covers the package-native route for:

  • checking whether a design is connected enough for a common scale
  • exporting anchor candidates from an existing fit
  • screening differential facet functioning (DFF)
  • deciding whether subgroup contrasts are linked and available for screening

For a broader workflow guide, see vignette("mfrmr-workflow", package = "mfrmr"). For the shorter help-page map, see help("mfrmr_linking_and_dff", package = "mfrmr").

First example: reuse selected criterion locations

An anchor is a parameter value held fixed during estimation. A shared Person, rater or task is an observed link; sharing an identity does not require fixing its value. For example, a direct Rater anchor at 0.35 logits holds that rater’s location at 0.35, whereas a group anchor at 0.20 for two raters fixes their sum at 0.40 and lets their individual values differ.

Start by loading the packaged synthetic teaching ratings. Each row is one Person’s score from one Rater on one Criterion, on a 1–4 rubric. We split the 48 Persons into two teaching cohorts with the same four raters and four criteria. This illustrates reuse of known identities; it is not empirical evidence that a real rater or criterion stays invariant over time.

library(mfrmr)
ratings <- load_mfrmr_data("example_core")
head(ratings[, c("Person", "Rater", "Criterion", "Score")])
people <- unique(ratings$Person)
baseline_data <- ratings[ratings$Person %in% people[1:24], , drop = FALSE]
new_data <- ratings[ratings$Person %in% people[25:48], , drop = FALSE]

Fit the reference and select its Criterion locations. make_anchor_table() requires a numerically eligible source, but does not establish substantive invariance. If it refuses a source, inspect that model’s diagnostics; exporting with readiness_policy = "review" is for inspection, not for bypassing the requirement in a new calibration.

baseline <- fit_mfrm(
  baseline_data, "Person", c("Rater", "Criterion"), "Score",
  method = "MML", rating_min = 1, rating_max = 4,
  category_policy = "preserve"
)
anchors <- make_anchor_table(baseline, facets = "Criterion")
anchors

The columns name the facet, its exact level ID, and its fixed location in internal logit coordinates. They do not contain thresholds, slopes or source standard errors. Values transformed for display with Umean/Uscale must not be copied into this table as though they were internal logits. The default digits = NULL preserves fitted values for reuse. Rounding each row can break a whole-facet zero sum, so round a display copy rather than the anchor input.

Review the intended constraints against the receiving data before fitting. Unknown IDs, duplicate rows and incompatible targets need resolution; keeping the last duplicate row mechanically does not decide which value is justified.

anchor_review <- review_mfrm_anchors(
  new_data, "Person", c("Rater", "Criterion"), "Score", anchors = anchors,
  rating_min = 1, rating_max = 4, category_policy = "preserve"
)
anchor_review$issue_counts
anchor_review$anchors
anchor_review$recommendations

The recommendation about five anchors is a configurable count screen, not a universal minimum or proof that a design is linked. FreeLevels counts levels outside direct/group constraints, not independent parameters: group members can vary subject to their mean, while centering removes a degree of freedom.

Now fit the new cohort. This example fixes all four Criterion locations, so that facet has no unanchored remainder. Rater locations and category thresholds are estimated again. The same rubric is specified explicitly in both fits.

linked <- anchor_to_baseline(
  new_data, baseline, "Person", c("Rater", "Criterion"), "Score",
  anchor_facets = "Criterion", anchor_policy = "error",
  rating_min = 1, rating_max = 4, category_policy = "preserve"
)
summary(linked)
linked$fit$facets$others
linked$drift[, c("Facet", "Level", "Baseline", "New", "Drift")]

Read linked$fit$facets$others for the fitted facet locations. linked$drift compares only retained fixed non-Person anchors: its zero differences are expected by construction and do not test stability. For independent screening, fit waves separately and use detect_anchor_drift(), retaining its offset, common-element and uncertainty limitations. Keep the full linked object when saving the analysis, so its fitted model and supplied anchors stay together.

Limits that matter before using real data

  • Whole-facet centering includes anchors. Unless a facet is noncenter_facet, centering_scope = "facet" makes all its levels sum to zero. With R01 = 0.70, the other ungrouped raters sum to -0.70; a single remaining rater is fixed at -0.70. Group totals also contribute. Incompatible totals stop before fitting, even when anchor_policy = "silent". centering_scope = "remainder" reproduces the earlier restriction that the ungrouped, unanchored levels sum to zero. Saved results are not converted by reloading them; fitting under a different convention requires re-estimation. For ordinary additive RSM/PCM JML, centering_scope = "anchor_origin" instead lets direct or group anchors replace their facet’s centering, as FACETS does. Choose an unanchored, active noncenter facet and repeat the same arithmetic mean target for each group member. This does not change the default or account for estimated-anchor error.
  • The helper does not copy every setting. The model, estimation method, centering convention and MML integration mode are inherited automatically. Older baselines without convention metadata retain "remainder". Repeat the intended category policy, rubric, orientation, PCM/GPCM roles, uncentered facet and population model. RSM/PCM MML without a population model fixes ability to a standard-normal distribution; it does not estimate a changed cohort mean/variance. An explicitly requested population_formula = ~ 1 estimates normal-population moments and needs person_data; see help("fit_mfrm") for its assumptions.
  • Person anchors require JML. Current MML integrates ability and rejects fixed Person values or Person group means. Common Persons can be present in the design without being anchored. Choosing JML changes the estimator and should follow the analysis question, not merely avoid an error.
  • Anchor uncertainty is conditional. The new fit treats supplied values as exact. It does not propagate their source estimation error; an unavailable SE for a fixed value does not mean its source was perfectly known. Compare defensible anchor sets when conclusions depend on that choice.
  • Locations are not the entire calibration. To hold thresholds and other supported calibration components fixed while scoring, use extract_mfrm_calibration(), validate and freeze the saved calibration, then call score_mfrm_calibration(). See help("mfrm_calibration_workflow") for its supported models and required checks.

The FACETS centering rules help distinguish an origin constraint from a fixed external value, but are not mfrmr’s partial-anchor convention. Uto (2021, pp. 1442–1444) explains common-rater/task linking and its design dependence. That simulation fixes generated common parameters and removes a redundant rater constraint; its Bayesian estimation does not validate mfrmr’s different constraints or supply uncertainty propagation for estimated anchors.

Annual speech contests with common recordings

Suppose each year’s contestants give a three-minute English speech. Most judges return and use the same rubric. Before the contest, they rate a set of recorded speeches used in previous years. You want to know whether judges became more severe, whether the whole panel changed its standard, and whether the new contestant group performed differently on a common scale.

The common recordings offer a link: the performance in a fixed recording does not improve from one year to the next. Its interpretation must still be comparable under the rubric and viewing conditions. An unchanged time limit or criterion name alone does not establish this. Because contestants change, a difference between annual groups is not individual growth.

This section explains the design and the limits of current functions. A complete recording-based annual analysis, including formal year-difference intervals, is not yet verified in mfrmr. The teaching cohorts in the first example above do not contain annual reratings of common recordings.

Identify the performance, judge and rating occasion

Keep one row per individual rating on one criterion. The following IDs illustrate identities to preserve; they are not supplied example data.

Observation Performance ID Judge ID Rating year
Judge A rates reference video V01 in 2025 V01 A 2025
Judge A rates that same video in 2026 V01 A 2026
Judge A rates a new 2026 contestant’s speech Speech_2026_01 A 2026

Also retain criterion, score, session, training phase and video/live mode. The same speaker giving a new speech needs a new performance ID when the measurement target is that speech. Preserve individual ratings before discussion or disclosure of reference scores. Consensus scores alone cannot recover differences among judges. Include performances spanning relevant levels and criterion profiles; there is no universal adequate recording count. The five-common-element helper warning is not such a rule.

Choose what is shared and what is allowed to change

In joint calibration, analyze years together, sharing an unknown measure for each common recording while allowing judges’ severities to vary by year. A judge-year effect represents a particular judge in a particular year; retain the original judge ID so these effects can later be compared. The recording measures can be estimated rather than supplied as numerical anchors.

In fixed-reference calibration, use previously estimated recording measures as fixed values for a later year and estimate that year’s judge effects. This preserves a chosen reference scale but conditions on its estimated values. When the recordings take the Person role, current mfrmr requires JML for direct Person anchors; MML rejects them. Sharing unknown performance measures is a different design and does not require these anchors. Formal JML structural intervals remain unqualified.

Returning judges should not automatically be fixed to their previous severities when their changes are the question. A panel mean fixed separately in every year also prevents estimating a common shift. For example, centering away a +0.40-logit increase for all judges would leave no panel-wide increase to report. FACETS describes group anchoring as an assumption about average severity, not proof that the panel stayed stable (Linacre, 2012, p. 9).

Specify scale constraints, criterion/category stability and ability-population assumptions together. Unrestricted year effects and judge-year effects would overlap; freely changing criteria can also absorb a common scoring shift. Separate fixed-standard-normal MML fits do not estimate changing cohort means. In a joint model, do not assign conflicting Person-level year covariates to a common recording rated in several years. Its rating occasion is not a different underlying performance.

When judges are the linking set, detect_anchor_drift() subtracts their common shift. If all selected differences are +0.40 logits, LinkOffset is +0.40 and every residual Drift is zero. This describes relative alignment, not evidence that the panel was stable. Interpreting LinkOffset itself as panel change is also unjustified without a separate scale reference.

Agreement after training, operational stability and correctness against an expert benchmark are different outcomes. Adding two squared SEs assumes away covariance; marginal interval overlap is not a test of change. Which uncertainty is available with anchors?

An anchor does not make every interval unavailable. For ordinary unit-weight RSM/PCM MML with a fixed standard-normal population and fixed-grid integration, mfrm_facet_intervals() can supply model-information or cluster-sandwich intervals for free facet locations and contrasts, subject to its checks. They condition on the supplied anchors. A fixed target has SE zero and no inferential bounds; this does not describe the uncertainty of its original calibration.

If the population mean and variance are also estimated, anchored point estimation is supported, but the native location and population interval helpers currently exclude anchors and group constraints. Inspect fit$readiness$fit: EstimabilityState = "not_evaluated" means the identification review is incomplete, not that numerical optimization failed or the model was proved unidentified. The separate fit$data_review$estimability$nonlinear_local_estimability can pass its local-rank check while overall readiness remains under review. That local result alone does not authorize intervals or exporting anchors for reuse. Choose the population assumption for the assessment question, not simply because one configuration supplies intervals.

For one-family GPCM, model-information and cluster-sandwich slope and curve intervals can include fixed facet anchors or group means when their own numerical checks pass. Use confint(fit, parm = "slopes") for relative slopes and mfrm_curve_intervals(fit, newdata) for curves at specified ability values and rating contexts. Their returned explanations state that source-anchor uncertainty is excluded. Fixing a rater’s location does not fix its slope, category thresholds or entire response curve. A group mean does not fix each member.

The restrictions differ by output. Anchored one-family GPCM currently has no native-location or profile-slope interval route, and no portable-calibration export. Fitted-object scoring with predict_mfrm_units() has separate source and scoring checks. An available slope interval does not certify that source for scoring: its finer-grid integration check may still fail. Explicit readiness_policy = "review" retains review-only values and does not make them operational scores. These distinctions also apply after saving results.

CenteringScope = "remainder" describes the fitted constraint, including for native files saved before this field existed. Do not assign a new value to fit$config$centering_scope or recenter its coefficient table: the likelihood, parameter mapping and uncertainty still belong to the original fit.

Both fits keep R01 at 0.70. The remaining raters sum to zero in the legacy fit and -0.70 in the whole-facet fit. This changes R01’s comparison with the other raters; it is not just a renamed column. Retain the two analyses under different filenames, and report the convention with the other model settings. Complete facet anchors can also become incompatible with a whole-facet zero sum. Resolve that model specification explicitly rather than rounding anchors or silently switching the population model.

For more complex analyses, build_mfrm_replay_script(restored_fit, data_file = "ratings.csv") provides a recipe with stored anchors, group means and the original convention. It requires the original analysis data at the specified path. Review its generated fit_mfrm() call before deliberately changing the convention; preserve population covariates, category handling, orientation, uncentered facets and PCM/GPCM owners. This recipe refits. By contrast, the replay written by export_mfrm_results() reopens its saved results bundle without reconstructing the model.

If only a frozen calibration survives, retain its original scoring meaning. Generic old identification labels are insufficient to infer its centering convention. See vignette("mfrmr-portable-calibration", package = "mfrmr") for re-extraction and validation; changing a label is not recalibration. Earlier MML fits containing Person anchors require special review because those values were ignored. Current fitting rejects them; choosing centering_scope = "remainder" does not repair that earlier analysis.

An anchor is a fixed value in all three programs, but the surrounding constraints determine what that value means. Copying a number from another program is insufficient when its parameterization or population model differs.

For ConQuest, read import together with set; importing anchors alone does not specify all location and scale constraints. Parameter indices must be checked against the actual model design and retained levels. A changed index can fix the wrong coefficient without a syntax error.

For example, let four rater severities be \(\gamma_1,\ldots,\gamma_4\), with R01 fixed at \(\gamma_1=0.70\), and no group constraints:

The second row applies, for example, to TAM’s tam.mml.mfr(formulaA = ~ item + rater + step, constraint = "cases") and ConQuest’s model task+rater+step with lconstraints=cases. Those settings also leave the first task term uncentered, unlike mfrmr’s default. These are specific model configurations, not universal software conventions. The different rater contrasts show why applying the same anchor and then shifting the final locations is not generally an equivalent analysis. Group-mean anchors need corresponding linear constraints; fixing every member to the group mean would impose a different model.

For unit-slope RSM/PCM with all facet locations centered and an estimated population mean \(\mu\), another equivalent origin uses a zero population mean and uncentered task locations: set \(\theta'=\theta-\mu\) and \(b'_{task}=b_{task}-\mu\). Rater severities, centered step ladders and population variance stay the same, so every response probability is unchanged. This mapping applies to the configuration with Rater anchors above. If a task value is also anchored, its constraint must be transformed with it. In particular, estimating population variance and fixing it to one are different models; moving the origin does not reconcile that difference. Checking this mapping is distinct from running and comparing both programs’ optimizers.

To compare programs, first match the ratings, category coding, response probabilities, free and fixed parameters, and population assumptions. A coordinate transformation must carry the anchors and population parameters with it. Then check numerical integration and optimization. Finally compare SEs for the same parameter or contrast, transforming the covariance matrix when coordinates differ. A point-estimate match alone does not validate an uncertainty method or include source-anchor uncertainty.

A bounded check using all 48 Persons, four raters and four criteria in example_core illustrates both outcomes. Under the whole-rater constraint above, TAM 4.3.25 and ConQuest 5.47.5 agreed to within \(3.1\times10^{-6}\) in their free response-design coefficients. A separate explicit TAM design representing mfrmr’s legacy remainder constraints agreed with that mode to within \(1.8\times10^{-7}\), when mfrmr used 81-point Gauss–Hermite integration. Both comparisons fixed ability to \(N(0,1)\). For the latter comparison, 31-point integration in that legacy mode left a maximum coefficient difference of about 0.00067; increasing integration precision resolved it. Equal node counts across programs do not guarantee equal quadrature rules or accuracy.

This checks one RSM configuration and its point estimates, not general compatibility for PCM, GPCM, group constraints, JML or SEs. It does not make 81 points a universal requirement. More importantly, being able to reproduce mfrmr’s restricted model in another program does not establish that its partial-anchor constraints answer a particular linking question. Decide which locations and population moments should remain free before choosing the model.

1. Check connectedness first

Use subset_connectivity_report() before interpreting subgroup or cross-form contrasts.

sc <- subset_connectivity_report(fit, diagnostics = diag)

sc$summary[, c("Subset", "Observations", "ObservationPercent")]
plot(sc, type = "design_matrix", preset = "publication")

Interpretation:

  • Sparse rows or columns indicate weaker design coverage.
  • Weak coverage should lower confidence in subgroup comparisons.
  • Use the co-observation design graph, not rater agreement, severity-direction, or halo response networks, to assess empirical connectedness. Response-network correlations do not create a common scale.

2. Export anchor candidates

make_anchor_table() mechanically exports fitted values in the direct-anchor schema. Its output is a candidate table, not a validated anchor set.

anchors <- make_anchor_table(fit, facets = "Criterion")
head(anchors)

By default, make_anchor_table() refuses a source whose current readiness record does not have InferenceReady = TRUE. Use readiness_policy = "review" only to inspect review-only candidate values, not to reuse them as anchors. For a ready reference fit, also document cross-run element identity and invariance and confirm compatible model, score, orientation, and population conventions. Then use review_mfrm_anchors() to check table syntax and receiving-data support. That review does not certify the substantive link.

Keep the roles distinct: common ratings or common elements supply observed design overlap; anchors fix individual parameters; group_anchors constrain a group mean under an externally justified target or equal-mean assumption. Neither constraint type manufactures empirical overlap.

Design the link, not only the percentage

No anchor percentage or count is universally adequate. In sparse designs, link quality also depends on coverage, the distribution and redundancy of the links, whether one articulation point or critical edge holds the network together, the location and model fit of the linking set, and the intended use of ranks or classifications. Inspect both Rater-centered and Person/task- centered assignment graphs rather than treating a minimum count as proof of a common scale. This distinction is consistent with work on sparse linking networks by Myford and Wolfe (2000), Wind and Jones (2018), and Uto (2021).

Fixed anchor values also carry uncertainty from their source calibration. Current mfrmr drift and chain summaries do not propagate every source-fit, offset, and cross-fit covariance component. When results depend on the anchor set, compare defensible alternatives and report that sensitivity. Robitzsch (2024, pp. 1181–1182, 1187–1188) examines a different source of linking error: random uniform DIF in fixed-item 2PL calibration. Its derivation neglects Person sampling error and does not provide a variance estimator for fitted population parameters. It supports checking invariance, not claiming that mfrmr propagates all linking uncertainty.

3. Compare group residuals

Residual comparisons describe how observed-minus-expected scores differ between groups. They use score units and do not test differential functioning.

A group with higher average ability can score higher without differential functioning. DFF concerns a facet difference at the same ability. Residual screens inherit the fitted population assumptions, and fixed-standard-normal RSM/PCM subgroup refits do not estimate group ability distributions. Linking anchors alone do not address an omitted group difference. Review these assumptions before interpreting a residual difference involving a rater or criterion.

Representing group ability differences is necessary for a suitable population model, but does not turn the current residual screen into a calibrated DFF test. MML residuals evaluate expected scores at EAP ability estimates. Because the response function is nonlinear, a no-DFF model can still have different mean residuals across groups. This concerns the null being tested as well as its standard error.

The residual method therefore returns no p-values, confidence intervals or positive/negative classifications. For compatibility, its former SE and test columns contain NA. Recompute older residual results with analyze_dff() using the existing fit and original data; no model refit is needed.

dff_resid <- analyze_dff(
  fit,
  diag,
  facet = "Criterion",
  group = "Group",
  data = bias_df,
  method = "residual"
)

screen <- plot(dff_resid, type = "summary")
comparisons <- plot_data(screen, "pairs")
comparisons[, c("Level", "Group1", "Group2", "Contrast",
                "N_Group1", "N_Group2", "PlotStatus")]

Read the figure and this table together:

  1. The labels follow Level | Group1 | Group2. Contrast subtracts the residual mean of Group2 from that of Group1. A positive value means higher residual scores in Group1, not established leniency, favoritism or unfairness.
  2. N_Group1 and N_Group2 count retained ratings, not independent Persons. Repeated ratings can make these counts large even when few Persons contribute. The same table has NPersons_Group1 and NPersons_Group2 for distinct Persons.
  3. PlotStatus separates displayed comparisons from finite comparisons omitted by top_n and comparisons with unavailable contrasts. None of these display states is a DFF decision. For an unavailable row, inspect sparse and the counts: the residual pairwise contrast requires both cells to meet min_obs. An absent group has a count of zero, not a zero difference.

Check how the requested ratings matched the fitted responses. This matters before comparing screens from different data subsets:

cases <- plot_data(screen, "cases")
table(cases$Reason)
cases[!cases$Included, ]
plot_data(screen, "notes")

InputRow identifies a row of the supplied data; FitRow identifies its matched fitted response. Exclusion reasons distinguish a missing group, an invalid/missing response, and a response absent from the fitted data. A fully matched example has no excluded rows; this does not establish independence. Response exclusions and unavailable comparisons are different stages.

For a grid of the same pairwise differences, use plot(dff_resid, type = "heatmap", metric = "contrast"). The default heatmap instead shows each group’s mean observed-minus-expected score. That cell mean can appear even below min_obs; read its saved pairs$sparse and counts. The scaled-residual (metric = "t") and pairwise-contrast routes withhold values below this threshold. Missing cells/contrasts stay missing, not zero. If every contrast is unavailable, inspect dff_resid$dif_table or the contrast heatmap; the summary has no finite points to draw.

Reserve ScaleLinkStatus and ContrastComparable for refit-based contrasts; their residual-method values do not describe a failed link.

4. Refit DFF when subgroup comparisons are defensible

The refit route reports logit-scale point contrasts when subgroup linking supports a common scale. Any available SE or test statistic conditions on the baseline anchors and omits their uncertainty and cross-refit covariance; FormalInferenceEligible remains FALSE, even with adequate linking. The default refit linking screen requires at least five anchored levels in total across the non-target linking facets in each subgroup. A weak link withholds contrast SEs and p-values. Inspect LinkingAnchoredLevels, LinkingThreshold, and ScaleLinkStatus; five is a local screening threshold, not a universal adequate anchor count or proof of invariance. It differs from the per-facet common-element screen called LinkSupportAdequate in drift and link-review results.

Direct anchors on the target facet and JML Person anchors remain fixed during subgroup refits. Check Fixed1 and Fixed2: when either is true, the row retains its estimates but has no contrast, SE or test. Supplying the same rater severity in both groups cannot establish that the rater functions equally across groups. Residual DFF can describe response departures under those constraints. To estimate a free target contrast, explicitly fit a baseline with the intended target constraints first. Older saved refit DFF objects may have dropped target or Person anchors; rerun analyze_dff() from the baseline fit to obtain subgroup estimates under the corrected rule. Loading an old result does not change it.

Check ComparisonStatus and ComparisonReason before interpreting a number. A failed or skipped subgroup fit has no subgroup estimate; the baseline value is not a replacement. An absent target level remains in the comparison table with a missing contrast. N_Group1 / N_Group2 count retained responses for that target level, while N_Subgroup1 / N_Subgroup2 count all retained responses in the subgroup. Failed fits have unknown retained counts, not zero; their input counts remain in $group_fits[[group]]$N_Input.

Sparse cells, missing SEs and Persons shared across the two subgroup fits withhold the independent-subgroup screen. Actual point estimates remain available, and ConditionalScreenReason explains missing uncertainty. Disjoint Person IDs alone do not establish independence or valid matching. The Welch degrees of freedom use response counts and are only a screening approximation. Older refit objects must be recomputed from the baseline and original data before using current summary, report or plotting methods; regenerate their exported tables and figures as well.

Bias screening answers a different question: estimate_bias() estimates an additional shift for each cell while holding the calibration fixed. A positive Bias Size raises the expected score. An anchored rater can still have a nonzero cell shift and a conditional SE for that shift. This SE does not include uncertainty in the fitted calibration or the supplied anchors, and it is not a joint-interaction confidence interval. Obs-Exp Average is the observed-minus-expected average under the baseline calibration, before fitting the shift. AfterBiasObsExpAverage records the remaining discrepancy with that shift included. Both are on the score scale; Bias Size is in logits.

Refits currently refuse baselines with user-specified active population models, fitted facet interactions, or group-anchor constraints because those structures cannot yet be replayed and linked completely within subgroups. The default GPCM-MML identification intercept is handled separately. Residual DFF remains a screening alternative; see ?analyze_dff for the exact scope.

Comparing with MH or ordinal logistic DIF

mantel_haenszel_table() now supplies a separate binary MH comparison with explicit matching strata and one response per Person and target. Its default conditional exact inference uses stats::mantelhaen.test(); an asymptotic option is also available. analyze_dff() retains its residual and refit routes. ordinal_logistic_table() supplies the independent-Person cumulative-logit comparison through the optional ordinal package. Pooled repeated-rating comparisons remain planned work. First specify what each result describes:

Procedure Quantity being compared
Residual DFF Group difference in mean observed-minus-expected score; descriptive
Linked refit DFF Group difference in a facet parameter, conditional on baseline anchors
Binary Mantel–Haenszel (MH) A common group odds ratio conditional on declared matching strata
Cumulative ordinal logistic Group and matching-by-group terms in a proportional-odds response model

First declare the intended response roster and rating plan before running the methods. Passing that roster through residual analyze_dff(data = ...) now selects the fitted observations by Person, all facets, score, weight and repeated-response multiplicity. It uses the original fitted expectations, without recalibrating on the selected subset. The same contract applies to dif_interaction_table().

Inspect $cases in each result: residual output maps InputRow in the supplied data to FitRow in fit$prep$data; MH/ordinal output identifies input rows with Row. Missing groups, invalid responses and responses absent from the fit cannot silently acquire another observation’s residual. Requesting more copies than the fit contains is rejected. Identical fitted copies can be exchanged for this descriptive calculation only when their model moments agree; their FitRow assignment does not recover an occasion identity.

Residual N counts response rows, while NPersons counts distinct Persons. For example, 12 Persons with three criteria give 36 rows for a rater, not 36 independent Persons. Descriptive residual summaries can retain those rows; ordinary MH/ordinal inference cannot treat them as independent target responses. Earlier saved residual summaries must be recomputed from the saved fit and source data to obtain this matching audit; a model refit is unnecessary.

Method-specific exclusions can still differ: MH removes uninformative strata, whereas ordinal models may retain their observations. Report these differences and the matching rule; do not automatically intersect outcome-dependent inclusion masks and treat that as a prespecified common cohort. Matching rows is necessary for understanding a comparison, but does not make the methods’ quantities or null hypotheses identical.

The MH result keeps the MH point estimate separately from the conditional maximum-likelihood estimate used by exact inference. Its strata and cases tables retain group/category counts, opposing effects, missing responses and strata without overlap. Supply multiple matching columns, such as total and rating plan, through strata; continuous values are not silently binned. The function rejects duplicate Person-target cells. Pointwise intervals are not simultaneous across targets; Holm adjustment applies to p-values only. Exact probability-ordered two-sided p-values need not invert equal-tail confidence intervals. See ?mantel_haenszel_table for a runnable example.

The ordinal result fits matching-only (M1), matching plus group (M2), and matching plus group and their interaction (M3) to identical complete rows. Its table separates uniform (M2/M1), nonuniform (M3/M2) and joint (M3/M1) likelihood-ratio tests, with Holm adjustment across all three tests and targets. DeltaNagelkerkeR2 names the pseudo-R-squared definition explicitly. The contrasts table reports M3’s reference/focal upper-tail odds ratios at the endpoints and midpoint of the overlapping matching ranges; values above one favor higher reference scores. Fits use all complete responses. An interaction means this odds ratio changes with matching, so one constant group coefficient does not summarize the full difference.

The separate proportional_odds table tests whether slopes can differ across category cuts, using a global nonproportional alternative. This diagnostic has its own multiplicity family and does not select which group tests are run. For binary responses it is not applicable. models, matching and cases preserve convergence information, group ranges and row exclusions. Empty declared categories, absent range overlap and numerical failures remain unavailable; repeated rows are rejected. See ?ordinal_logistic_table for a runnable example and the exact numerical checks. All reported p-values are asymptotic: convergence or a nonsignificant diagnostic does not establish adequate small-sample inference or proportional odds.

A bounded known-model check illustrates this limit. With three categories, balanced groups, a fixed matching grid and total N=40, all 1,000 simulated data sets had computable group tests. Under no group difference and true proportional odds, the unadjusted joint test rejected in 65/1,000 cases (6.5%; 95% Monte Carlo Wilson interval 5.1%–8.2%). The proportional-odds diagnostic was unavailable in 42 cases and rejected in 114/958 available cases (11.9%; interval 10.0%–14.1%), at nominal 5%. Treating its numerical availability as assurance of a valid 5% test would therefore be misleading. For the default Holm-adjusted family of three group tests, at least one rejection occurred in 52/1,000 cases (5.2%; interval 4.0%–6.8%). This family is separate from the proportional-odds diagnostic and does not repair it. At N=200 and N=1,000 under the same mechanism, joint rejection was 4.7% and 4.6%, and diagnostic rejection was 5.8% and 4.5%, with all results available. These particular conditions do not establish a universal sample-size rule. The function offers asymptotic comparisons, not qualified small-sample tests. No significance cutoff or numerical tolerance was changed in response to these results; the diagnostic does not determine whether group comparisons are run.

Matching is a substantive choice. In the binary Rasch case with a common item set and invariant other items, conditioning on the total including the studied item removes the group ability distribution from that item’s conditional response. Removing the studied item can leave group differences even without IRT DIF (Holland and Thayer, 1986, pp. 14–18). This is not a general endorsement of any total score. Contamination by other DIF items, missing responses and different rater/task plans require separate attention. In a many-facet assignment, two persons with the same total may have faced different raters or tasks. Specify common exposure or an explicit plan adjustment with overlap before treating their totals as comparable.

For each target, retain the persons, group coding, category order, matching definition, exclusions and rating plan. Repeated ratings from a Person are not independent new persons in ordinary MH tables or logistic likelihoods. A comparison must account for that dependence; silently averaging ratings changes the response being analyzed. Connectedness alone does not resolve either problem.

MH can miss effects that reverse direction across matching strata. Rogers and Swaminathan’s study also used different purification procedures for MH and logistic regression, so its comparison is not solely a change of test statistic (1993, pp. 111–115). Report uniform and nonuniform terms separately when fitting a logistic comparison. In Zumbo’s three-model sequence, add the group term to the matching-only model, then add the matching-by-group interaction; the joint test compares the last model with the first (1999, pp. 23–27).

The cumulative proportional-odds assumption in that ordinal model is different from the adjacent-category structure of RSM/PCM and is not generally satisfied by it. Check the matching-response relationship and model adequacy before interpreting a difference between procedures as DFF. Pseudo-R-squared definitions and their changes must be named: the historical .130 screen in Zumbo’s application is not a universal cutoff or a default for mfrmr. A nonsignificant result is not evidence that differential functioning is absent, and statistical DIF alone does not establish bias.

Zumbo, B. D. (1999). A handbook on the theory and methods of differential item functioning (DIF): Logistic regression modeling as a unitary framework for binary and Likert-type (ordinal) item scores. Ottawa, ON: Directorate of Human Resources Research and Evaluation, Department of National Defense.

Compare an explicitly shared response roster

The following self-contained example puts the three procedures beside each other. It requires the optional ordinal package. The binary Rasch design has 240 independent Persons answering the same eight items once each. Both groups have the same item difficulties, but different ability distributions. These synthetic data illustrate how to assemble and audit a comparison; this one sample is not a validation study or a recommended sample size.

Here Total includes the studied item and is computed only after checking the complete common item roster. MH conditions on each total separately; the logistic models instead assume a linear relationship with total on the logit scale. Even in this Rasch example, those are different matching models. The residual calculation uses the fitted Person and item parameters.

library(mfrmr)
set.seed(241010)
group_order <- c("Reference", "Focal")
person_group <- rep(group_order, each = 120)
ability <- rnorm(240, mean = ifelse(person_group == "Focal", 0.5, -0.5))
shared <- expand.grid(Person = seq_len(240), Item = paste0("I", 1:8),
                      KEEP.OUT.ATTRS = FALSE, stringsAsFactors = FALSE)
shared$Group <- person_group[shared$Person]
difficulty <- setNames(seq(-1, 1, length.out = 8), paste0("I", 1:8))
shared$Score <- rbinom(nrow(shared), 1,
  plogis(ability[shared$Person] - difficulty[shared$Item]))
stopifnot(!anyNA(shared), all(table(shared$Person, shared$Item) == 1L))
shared$Total <- ave(shared$Score, shared$Person, FUN = sum)

shared_fit <- fit_mfrm(shared, person = "Person", facets = "Item",
                       score = "Score", method = "JML", model = "RSM")
residual <- analyze_dff(shared_fit, facet = "Item", group = "Group",
  data = shared, focal = group_order[2], method = "residual")
mh <- mantel_haenszel_table(shared, person = "Person", target = "Item",
  score = "Score", group = "Group", strata = "Total", groups = group_order)
ologit <- ordinal_logistic_table(shared, person = "Person", target = "Item",
  score = "Score", group = "Group", matching = "Total",
  groups = group_order, categories = 0:1)

First retain each method’s response audit. The join below uses original row numbers from the same shared data, not the position of a row in a result table. It retains exclusions rather than choosing the intersection of the methods’ retained rows. With one response per Person-item, the counts below are also distinct-Person counts within each item and group.

case_audit <- rbind(
  data.frame(Method = "Residual", Row = residual$cases$InputRow,
    Included = residual$cases$Included, Reason = residual$cases$Reason),
  data.frame(Method = "MH", mh$cases[c("Row", "Included", "Reason")]),
  data.frame(Method = "Logistic", ologit$cases[c("Row", "Included", "Reason")])
)
case_audit$Target <- shared$Item[case_audit$Row]
case_audit$Person <- shared$Person[case_audit$Row]
case_audit$Group <- shared$Group[case_audit$Row]
case_audit$Count <- 1L
case_counts <- aggregate(Count ~ Target + Method + Group + Included + Reason,
                         data = case_audit, FUN = sum)
case_counts[case_counts$Target == "I2", ]

Next align effect direction explicitly. focal above makes the residual contrast Reference minus Focal. All odds ratios below are Reference/Focal odds of a higher score. Thus a positive residual difference and an odds ratio above one point in the same score direction, but their magnitudes cannot be compared. The MH column uses the conditional maximum-likelihood estimate from the default exact analysis; the distinct MH estimator remains in mh$table$MHOddsRatio. Logistic values come from M3 and can change direction over total scores. Keep their matching values and numerical status visible.

r <- residual$dif_table
stopifnot(all(r$Group1 == group_order[1]), all(r$Group2 == group_order[2]))
effects <- data.frame(Target = r$Level, ResidualDifference = r$Contrast,
  ResidualStatus = ifelse(is.finite(r$Contrast), "descriptive", "unavailable"))
m <- mh$table[c("Target", "OddsRatio", "Status")]
names(m)[2:3] <- c("MH_ExactOR", "MH_Status")
effects <- merge(effects, m, by = "Target", all = TRUE)
mid <- subset(ologit$contrasts, Position == "OverlapMid",
              select = c(Target, Matching, OddsRatio, Status))
names(mid)[2:4] <- c("TotalAtMidpoint", "Logistic_MidOR", "Logistic_Status")
effects <- merge(effects, mid, by = "Target", all = TRUE)
effects[effects$Target == "I2", ]

# Preserve endpoint effects; a midpoint alone can conceal a crossing effect.
subset(ologit$contrasts, Target == "I2")
subset(mh$table, Target == "I2", select = c(Target, NReference, NFocal,
  Lower, Upper, PValue, PAdjusted, Status, IntervalStatus))
subset(ologit$table, Target == "I2", select = c(Target, Comparison,
  DeltaNagelkerkeR2, PValue, PAdjusted, Status))

In the displayed sample, residual and logistic calculations use 120 Persons per group for I2. MH uses 96 Reference and 97 Focal Persons; its audit accounts for the other 47 responses in constant-response strata. This is a difference in usable conditional information, not an unnoticed change of the input roster. At total 0 or 8, the item response is determined by the total itself. Logistic endpoint odds ratios are predictions from its smooth response model; they are not empirical odds ratios in those degenerate strata. Overlapping matching ranges alone do not establish response support or a correct linear logit relationship. A binary proportional-odds diagnostic cannot check that relationship.

All eight items were analyzed before displaying I2, chosen in advance as the example target. MH adjusts across eight item tests; logistic adjusts across 24 item-by-comparison tests. These are separate families, not an adjustment for selecting among methods. Residual differences have no p-values. MH’s intervals are pointwise; logistic contrasts here have no intervals. For these binary data the proportional-odds diagnostic is not_applicable_binary, not evidence that proportional odds holds for a future ordinal analysis.

Read the case counts before interpreting different results: MH can omit constant-response or single-group strata that logistic retains. Logistic Included = TRUE means a row was supplied to a model, not that estimation succeeded; inspect the effect/test statuses and ologit$models. A missing effect stays NA, with its reason, rather than being replaced by zero or removed from the comparison. The descriptive JML residuals do not acquire inferential validity from the other methods’ p-values.

To retain this analysis, save the input, matching definition, calibration and complete results together. Later displays can be rebuilt from this object without rerunning the models.

comparison <- list(data = shared, groups = group_order, categories = 0:1,
  matching_rule = "Complete common eight-item total, including the target",
  fit = shared_fit, residual = residual, mh = mh, ordinal = ologit,
  effects = effects, case_audit = case_audit, case_counts = case_counts,
  session = sessionInfo())
saveRDS(comparison, "dff-comparison.rds")

For actual ordinal scores, retain the declared categories and omit ordinary binary MH; do not dichotomize merely to fill this table. For a Rater target with several Criteria per Person, the repeated rows do not satisfy this example’s independence contract. Differing rater/task plans also require justified adjustment. Those extensions remain open. Agreement of signs or nonsignificant tests in this display is not a robustness, invariance or fairness classification.

6. Model-estimated facet interactions

Residual bias and DFF tools screen for unusual cells after fitting the additive model. For example, ask whether a rater scores particular criteria unexpectedly high or low after accounting for the main facet effects. estimate_all_bias() screens all non-Person facet pairs by default; specify pairs to limit the search. It holds the calibration and Person estimates fixed, so these cell shifts differ from jointly estimated interaction effects.

ratings <- load_mfrmr_data("example_bias")
fit_add <- fit_mfrm(
  ratings, "Person", c("Rater", "Criterion"), "Score",
  method = "MML", model = "RSM", quad_points = 31
)
screens <- estimate_all_bias(fit_add)
report <- mfrm_report(screens, study_context = c(
  question = "Which rater-criterion cells need substantive review?",
  score_direction = "Higher coded scores indicate better performance"
))
report$tables$overview
head(report$tables$bias_cells)
plot(screens)
# Keep complete tables, including failed pairs and unavailable cells.
export_summary_appendix(report, output_dir = "bias-review")

The signed Bias Size describes a shift in expected coded scores; positive does not necessarily mean favorable. Replace the declared direction with your rubric’s actual meaning. Report the searched interactions, exclusions, cell counts and unavailable results, rather than only flagged cells. The screening statistics omit calibration and Person uncertainty and have no collection-wide multiplicity control. Different pairs reuse observations; their cell counts must not be summed as the study sample size. This is a FACETS-like conditional exploration workflow, not a claim of identical algorithms, probabilities or calibration conventions. See the FACETS bias-estimation description.

Interpretation:

  • Name the facet pair explicitly before fitting.
  • Treat the interaction estimates as fixed-effect deviations from the additive MFRM under zero marginal-sum constraints.
  • Inspect sparse interaction cells before reporting substantive claims.
  • Keep this route separate from residual screening with estimate_bias().
  • Match observations, score coding, constraints, population specification and integration settings. Both example fits use 31 points; that is the minimum comparison gate, not proof of sufficient integration accuracy. Check stability of likelihood differences and conclusions with a finer common grid when needed.
  • AIC, BIC and SABIC compare eligible candidate models; BIC uses the number of Persons, not rating rows. Ranking and nested-LRT eligibility are separate. ConQuest also reports information criteria, but cross-software comparisons require matching likelihoods and parameter counts, not just table labels. See ConQuest commands.
  • Joint RSM/PCM interactions use direct optimization by default. With a fixed standard-normal population and fixed quadrature, mml_engine = "hybrid" initializes the fit with EM before direct finishing; "em" retains the EM solution with its common terminal-gradient review. Use mml_starts to examine specified initial values, and inspect summary(fit)$starting_values and fit readiness before comparing models. EM can be slower and does not resolve sparse-design identification or insufficient quadrature. The conditional cell screen itself is not EM.

7. Multi-wave anchor review

When you work across administrations, the route usually moves from a declared common-anchor design to anchored fitting and then to drift review. The block below is schematic: wave1 and wave2 must be administrations for which the listed facet levels have documented cross-wave identity and unchanged meaning.

Do not substitute ej2021_study1 and ej2021_study2 here. They are independent legacy synthetic studies; reused raw labels do not identify common persons, raters, or anchors and do not link their scales.

declared_common_facets <- c("Criterion")

fit1 <- fit_mfrm(
  wave1, "Person", c("Rater", "Criterion"), "Score",
  method = "MML"
)

anchored <- anchor_to_baseline(
  wave2,
  fit1,
  person = "Person",
  facets = c("Rater", "Criterion"),
  score = "Score",

)

  wave2, "Person", c("Rater", "Criterion"), "Score",

                           facets = declared_common_facets)
plot(drift, type = "drift", preset = "publication")

The current drift and chain helpers estimate one pooled offset across every selected common element and facet. Their SE ratios do not include uncertainty from estimating that offset or cross-fit covariance, and cumulative chain offsets have no propagated SE. Offset_SD is residual spread rather than an offset standard error. Use one coherent linking facet unless a common shift across facet blocks is defensible, and treat flags and support counts as review screens rather than formal tests or proof of scale equivalence.

Read OffsetStatus and OffsetReason when an offset is missing, and ScreeningFallback to see whether preliminary screening rejected every element and the calculation reverted to all finite differences. Contributing and N_Contributing distinguish elements actually used in the offset from those merely retained: when some rows have usable paired SEs, retained rows without them do not enter the weighted average. A singleton retained set has an undefined sample SD, so Offset_SD is missing and OffsetSDStatus explains why. Missing flags are reported separately from known flagged elements. These states preserve usable point estimates without representing unavailable precision as zero.

Subtracting an estimated offset also changes the residual covariance. The displayed SE ratio is therefore not guaranteed to be conservative. Consult SERatioStatus and FlagBasis: a magnitude-only Flag = FALSE does not mean the element passed an SE-ratio check.

Optional: explore rating assignments

There are two different meanings of an anchor. A common person supplies ratings that connect raters; their ability can remain unknown and estimated. A fixed anchor supplies a known parameter value to fit_mfrm(anchors = ...). The latter is not needed merely because several raters score the same person.

For example, the following existing simulation routes describe three practical assignments. Four common persons and eight raters illustrate the syntax; they are not recommended minimum counts. The common-person example uses more rating rows than the other examples, so this is not an equal-budget precision comparison.

library(mfrmr)

common <- build_mfrm_sim_spec(
  n_person = 40, n_rater = 8, n_criterion = 3, raters_per_person = 2,
  assignment = "sparse_linked",
  sparse_controls = list(link_persons = 4, link_raters_per_person = 8,
                         assignment_mode = "balanced")
)
rotating <- build_mfrm_sim_spec(
  n_person = 40, n_rater = 8, n_criterion = 3, raters_per_person = 2,
  assignment = "rotating"
)
random <- build_mfrm_sim_spec(
  n_person = 40, n_rater = 8, n_criterion = 3, raters_per_person = 2,
  assignment = "sparse_linked",
  sparse_controls = list(link_persons = 0, assignment_mode = "random")
)

# Use common, rotating, or random here to inspect the chosen assignment.
ratings <- simulate_mfrm_data(sim_spec = common, seed = 27309)

  ratings, person = "Person", facets = c("Rater", "Criterion"),
  score = "Score", include_agreement = FALSE

data_review$design_connectivity

The common-person design gives four persons all eight raters and the other 36 persons two raters each. The rotating and random designs give each person two raters. A random draw does not guarantee that all raters are connected or equally busy. For actual data, supply the planned assignment to describe_mfrm_data(expected_design = ...) to distinguish missing assigned ratings from cells that were never assigned.

Eckes’s discussion of rating designs distinguishes distributed overlap, a single common examinee, disconnected groups and task-nested spiral assignments (2023 edition, Section 9.1, Table 9.1, pp. 151–155). The rotating generator here uses the selected raters on all generated criteria. Use an explicit design_skeleton for task-specific assignments; do not equate ordinary rotation with every spiral design. Check model identification as well as graph connections, especially when raters are nested within tasks.

Connectedness means paths exist, not that those paths carry enough information. Review reliance on a small linking set, its composition, and sensitivity to loss of a linking person or rater. The ability to generate a sparse design is not a guarantee that a particular estimator or its intervals work well for it.
